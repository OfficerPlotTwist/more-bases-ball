# moreBasesBall — Simulation Analysis as a Service

**Status:** approved design, 2026-09-15
**Scope:** system-level design + decomposition. Each sub-project gets its own
implementation plan; this document is the contract between them.

## Summary

A baseball fan proposes a rule change in plain English. The system turns it into
a runnable simulation variant, runs it against real MLB player data alongside an
unmodified baseline, ranks the KPI shifts that actually moved, and publishes a
private results page. The fan is emailed a stat breakdown and texted a link plus
an infographic. Payment is by tier, where the tier buys **data depth** and
**rule expressiveness**.

## Decisions locked

| Decision | Choice | Why |
|---|---|---|
| What "forking the sim" means | Hybrid: rule DSL, with a code-writing agent as escape hatch | DSL covers the common space at ~$0.002/run and is deterministic; the agent covers everything else at ~$1.50–4.00/run |
| Data depth | All three tiers built; depth is the price ladder | One pipeline, C ⊃ B ⊃ A; depth is the clearest thing to sell |
| Escape hatch | **Human-gated.** Nik approves every generated fork before it runs | Arbitrary generated code must not run on our infra unreviewed |
| Review cadence | Batched daily queue + a manual "review now" button | Predictable 24h SLA without interrupt-driven review |
| Escape-hatch billing | Stripe authorize-then-capture | Nobody is charged for a rule that gets rejected |

## 1. Data spine

Extends `tools/build-data.mjs`, which today joins `statsapi.mlb.com` rosters to
the Baseball Savant sprint-speed CSV on MLBAM id and keeps nine batters per club
per season, 2021–2025.

Gaps it must close: **pitchers are entirely absent**, the player universe is
nine-per-club, and history stops at 2021.

Output layout:

```
data/
  seasons/{year}.parquet     1871+   batters AND pitchers, season lines
  events/{year}.parquet      1912+   Retrosheet, ~15M plate appearances
  statcast/{year}.parquet    2015+   rate stats, tracking
  pitches/{year}.parquet     2015+   pitch-level (Tier C only)
  players.parquet                    Chadwick register ID crosswalk
  coverage.json                      per-stat first/last year
```

Queried in-process with DuckDB over Parquet. No database server, no monthly DB
bill. Sources: MLB Stats API, Baseball Savant, Retrosheet, Lahman, Chadwick
Register — all free, none key-gated.

### Coverage table (also a product surface)

| Stat family | Source | Coverage |
|---|---|---|
| Season batting/pitching totals | Lahman, Stats API | 1871+ |
| Event-level play-by-play | Retrosheet | 1912+ near-complete; 1901–11 partial |
| Pitch-by-pitch loc/velo (PITCHf/x) | Savant | 2008–2016 |
| Statcast pitch tracking | Savant (Hawkeye 2020+) | 2015+ |
| Batted-ball EV / launch angle | Savant | 2015+ |
| Sprint speed, HP-to-1B | Savant | 2015+ |
| OF arm strength, catch prob / OAA | Savant | 2016–2020+ |
| Bat tracking (swing speed/length) | Savant | 2023+ |

`coverage.json` is generated by the build, rendered on every results page, and
enforced at intake: a rule requiring pitch tracking against 1927 is rejected
**before payment**, with the table shown as the reason.

## 2. Rule DSL

A JSON Schema–validated document. The LLM's only job at intake is to produce
one; it never writes simulation code on this path. Everything downstream of
intake is deterministic and reseedable, so two fans submitting the same rule get
identical numbers.

```json
{
  "ruleVersion": 1,
  "base": "mlb-2025",
  "geometry": { "bases": 5, "baseDistanceFt": 90, "moundDistanceFt": 65 },
  "counts":   { "balls": 4, "strikes": 3 },
  "outs":     { "perInning": 3 },
  "running":  { "forceChainEnabled": true, "tagUpRequired": true },
  "population": { "season": 2024, "teams": "all" },
  "run":      { "games": 10000, "seed": 20260915 }
}
```

Implementation: `sim.js`, `graphsim.js`, `ngon.js`, `trisim.js`, `layout.js`,
and `fielders.js` take a rules object in place of hardcoded constants.

**This is the riskiest change in the project.** The README publishes the classic
run environment (1 base ≈ 18 runs/game, 7 ≈ 6) as a result, and `AGENTS.md`
requires N-gon box scores stay byte-identical. See Testing.

## 3. Fork engine and the human gate

DSL path: intake → validate → run. Seconds, fractions of a cent.

Escape-hatch path (The Show only):

1. Stripe **authorizes** the charge; nothing is captured.
2. A subagent works in a dedicated git worktree, edits the simulation, and runs
   all twelve `tests/*.test.js`. Two automatic retries on failure.
3. On green tests, the rule, the diff, and the test output enter the **daily
   review queue**.
4. Nik approves or rejects in the operator console.
5. Approve → capture the charge, run the sim, publish. Reject → void the
   authorization, email the fan the reason.

Generated code never executes outside the worktree sandbox before approval.

## 4. Diagnostics

Baseline and variant run with the same seed and the same player population, so
every delta is attributable to the rule.

KPIs: runs/game, BA/OBP/SLG, HR/game, K%, BB%, steal attempts and success,
double-play rate, PA/game (a proxy for game length), and run-distribution
variance.

**Ranking is by effect size, not p-value.** At 10,000 simulated games any
difference is "significant," which makes p-values useless here. Each delta is
instead scored against that KPI's real season-to-season standard deviation from
the data spine: a shift of 2.4σ in runs/game means "larger than the gap between
any two consecutive real seasons," which is a sentence a fan can read.

## 5. Publisher

Renders a static results page per request to object storage at an unguessable
URL. Reuses `field3d.js` to show one signature play under the new rule — the
existing renderer already draws `entry.anim` and decides nothing, so it needs no
changes. Page includes the coverage table and the exact `rule.json`.

## 6. Commerce

Stripe Checkout for one-time (Sandlot) and subscriptions (Farm, The Show).
Authorize-then-capture for escape-hatch requests. Subscription revenue funds
page hosting; expiry moves a page to a "renew to restore" stub rather than
deleting it. Custom feature requests are quoted manually and invoiced.

## 7. Delivery

Email stat breakdowns via a transactional provider (~$0.001/message). SMS link
plus MMS infographic via Twilio (~$0.008 SMS, ~$0.02 MMS). The infographic is
rendered server-side from the same diagnostics JSON the page uses, so the text
and the page can never disagree.

## 8. Operator console

Nik's queue: pending rules, generated diffs, test output, approve/reject,
"review now". Gets a clickable launcher in
`C:\Users\nik\Documents\AI\Busdriver\dashboard\` per standing config.

## Error handling

| Failure | Response |
|---|---|
| LLM cannot map English to the DSL | The Show: offer escape hatch. Lower tiers: refuse with the nearest expressible rule suggested |
| Rule needs data the era lacks | Rejected at intake, before payment, with the coverage table as the reason |
| Generated fork fails tests | Two auto-retries, then rejected; authorization voided; fan emailed |
| Sim diverges from published classic results | Build fails. Non-negotiable |
| Delivery bounce (email/SMS) | Page still publishes; link retried, then surfaced in the console |

## Testing

- **Golden-run identity test (first task built).** Default `rule.json` must
  reproduce current `sim.js` output byte-for-byte. Until this passes, no new
  rule is expressible.
- The existing twelve `tests/*.test.js` are the regression gate every generated
  fork must clear. `tests/ngon.test.js` and `tests/defense-stress.test.js` are
  the load-bearing two.
- Runner rules tested as differentials on one play, per `AGENTS.md`.
- Diagnostics tested against a known no-op rule: a rule that changes nothing
  must produce deltas of exactly zero at the same seed.

## Build order

1. **Data spine** — pitchers, full player universe, Parquet + `coverage.json`
2. **Rule DSL + golden-run identity test** — parameterize the sims
3. **Diagnostics** — effect-size ranking against historical σ
4. **Publisher + results page**
5. **Commerce, delivery, operator console, escape hatch**

1 and 2 are the whole product's foundation. 3–5 are conventional by comparison.

## Out of scope (YAGNI)

Public rule gallery, user accounts beyond an email magic link, head-to-head rule
comparison, live in-season updates, minor-league data, a mobile app.
